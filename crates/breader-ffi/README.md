# breader-ffi: C interface

A small, stable C ABI over the `breader` facade (decision [D-064](../../docs/decisions.md#d-064)). Opaque handles, explicit ownership, no global state. The header is [`include/breader.h`](include/breader.h), generated by cbindgen and committed.

## Build

```
cargo build --release -p breader-ffi
```

produces `target/release/libbreader.so` (Linux), `libbreader.dylib` (macOS) or `breader.dll` with `breader.dll.lib` (Windows), and the static library `libbreader.a` (`breader.lib` on Windows). The crate is a workspace member but not a default member, so `cargo build` at the root does not build it.

The default feature `image` enables `breader_scan_file` (PNG and JPEG). Without it (`--no-default-features`) the function stays in the ABI and returns `BREADER_UNSUPPORTED`. The `rayon` feature of the facade is not enabled: a C caller does not expect a library to start a thread pool. Build with `--features breader/rayon` if you want it.

Linking: add `-Icrates/breader-ffi/include`, link `-lbreader`. The static library needs the platform's system libraries (`-lpthread -ldl -lm` on Linux, usually found by the compiler driver).

## Example

[`examples/c/scan.c`](examples/c/scan.c) reads a binary PGM (or a raw luma file, or a PNG/JPEG) and prints the symbols:

```
cargo build --release -p breader-ffi
cc -O2 -Icrates/breader-ffi/include crates/breader-ffi/examples/c/scan.c \
   -Ltarget/release -lbreader -Wl,-rpath,$PWD/target/release -o scan
./scan image.pgm
```

```c
BreaderOptions *opt = breader_options_new();
breader_options_set_effort(opt, BREADER_EFFORT_BALANCED);
breader_options_set_symbologies(opt, BREADER_MASK_QR | BREADER_MASK_EAN13);
BreaderReader *reader = breader_reader_new(opt);   /* copies the options */
breader_options_free(opt);

BreaderResults *results = NULL;
if (breader_scan(reader, rgb, rgb_len, w, h, w * 3, BREADER_PIXEL_RGB8, &results) == BREADER_OK) {
    for (size_t i = 0; i < breader_results_count(results); i++) {
        size_t n;
        const uint8_t *bytes = breader_result_data(results, i, &n);   /* raw payload */
        const char *text = breader_result_text(results, i, NULL);     /* UTF-8 or NULL */
        /* ... */
    }
}
breader_results_free(results);   /* invalidates every pointer taken from it */
breader_reader_free(reader);
```

## API

| Group | Functions |
| --- | --- |
| Library | `breader_version`, `breader_status_string` |
| Options | `breader_options_new`, `_free`, `_set_effort`, `_set_symbologies`, `_set_try_invert`, `_set_max_symbols`, `_set_time_budget_ms`, `_set_ean_addon`, `_set_code39_full_ascii`, `_set_code39_checksum` |
| Reader | `breader_reader_new(const BreaderOptions*)` (NULL for the defaults), `breader_reader_free` |
| Scan | `breader_scan(reader, data, len, width, height, stride, format, &out)`, `breader_scan_file(reader, path, &out)` |
| Results | `breader_results_count`, `breader_results_free`, and per index: `breader_result_symbology`, `_symbology_name`, `_data`, `_text`, `_content_kind`, `_gs1_hri`, `_corners`, `_orientation`, `_aim_id`, `_quality` |

Enumerations (`BREADER_EFFORT_*`, `BREADER_ADDON_*`, `BREADER_PIXEL_*` for luma8, rgb8, rgba8, bgra8, nv12, nv21 and i420, `BREADER_SYMBOLOGY_*`, `BREADER_CONTENT_*`) are `uint32_t` values with named constants; symbologies also have bit masks `BREADER_MASK_*` (18 of them, `BREADER_MASK_ALL`). Status codes: `BREADER_OK`, `BREADER_INVALID_ARGUMENT`, `BREADER_UNSUPPORTED`, `BREADER_PANIC`, `BREADER_IO_ERROR`.

## Ownership and threading

- Whatever a `*_new` function or a successful scan returns is owned by the caller and freed with the matching `*_free`. Freeing NULL does nothing. Never free twice.
- On failure `*out` is NULL. On `BREADER_OK` it is a results object, possibly with zero symbols.
- Pointers returned by the `breader_result_*` accessors (names, data, text, GS1 form, AIM id) belong to the results and stay valid until `breader_results_free`; they survive `breader_reader_free`. Do not free them.
- The pixel buffer given to a scan is only read during the call. `stride` is in bytes; 0 means tightly packed. For NV12, NV21 and I420 the chroma planes follow the luma plane (as in the Rust API).
- `breader_result_text` returns NULL when the text is ambiguous or contains a NUL byte; use `breader_result_data` (length-delimited) then.
- A reader and an options object are used by one thread at a time. Different readers may be used by different threads (the library has no global state). Results are immutable and may be read from any thread.
- Every function is null-safe and catches panics: a panic becomes `BREADER_PANIC` (or NULL/0 for accessors) and never unwinds into C. Enumeration arguments are validated, so an unknown value is `BREADER_INVALID_ARGUMENT`, not undefined behaviour.

## Versioning

The ABI follows the crate version: within a major version (while 0.x: within a minor version) functions and constants keep their meaning and signature; new functions and constants may be added. Treat unknown enumeration values returned by the library as "other". `breader_version()` returns the version at run time.

## Header

The header is regenerated with

```
cargo install cbindgen --locked --version 0.29.4
cbindgen --config crates/breader-ffi/cbindgen.toml --crate breader-ffi --output crates/breader-ffi/include/breader.h
```

and CI fails when the committed file differs.

## Tests

`cargo test -p breader-ffi`: Rust tests that call the exported functions (a QR code rendered in the test, every pixel format, null and invalid arguments, panic guard), and `tests/c_example.rs`, which compiles the C example and the header (as C99 with `-Werror -pedantic`, and as C++) with the system `cc` against the built library and reads a QR code with it. The C test is skipped when `cc` is missing and on Windows.
