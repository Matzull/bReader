# PDF417 (`breader-pdf417`, milestone M9)

Design of the PDF417 and compact PDF417 (decoding implemented in M9; detection, sampling and the reader in progress). Part of the cross-cutting [architecture](../ARCHITECTURE.md) (pipeline, traits, validation policy); status, spec references and read rates are in the [symbology index](README.md).

Scope: PDF417 and compact (truncated) PDF417, all error-correction levels, Macro PDF417 control blocks (parsed into metadata), ECI. MicroPDF417 and GS1 composite components are deferred to the "micro" group. The normative source is ISO/IEC 15438.

**Tests:** rxing's encoder (Apache-2.0) is a dev-dependency, to encode test symbols only; the `pdf417` crate (MIT) does not build on stable, so it is not a dependency: its pattern tables are transcribed into `spec/clusters.rs` with attribution and checked exhaustively in tests (4 bars and 4 spaces of width 1 to 6 over 17 modules, the cluster formula, all 2787 patterns distinct), and its published check codewords are test vectors for `Gf929::encode`. Clean-room: no decoder sources are read.

PDF417 is a stacked linear symbology, so the reader works on gray profiles like `breader-linear` (`uses_binary() == false`), not on the binary plane. Edge detection and run extraction are reused from `breader-linear` through a small `#[doc(hidden)]` API rather than duplicated. Modules: `spec` (cluster tables, row-indicator formulas, EC sizes), `decode` (codeword matrix to payload), `detect` (start/stop search and boundary fit), `sample` (row lines and codeword reading), `reader`.

1. **Start/stop search.** Scanlines from the linear scan plan (directions by effort). On the runs, match the start pattern (8 elements, 8-1-1-1-1-1-1-3 modules) and the stop pattern (9 elements, 7-1-1-3-1-1-1-2-1) with a quiet zone on the outer side, either reading direction. Each hit records position, module width and direction.
2. **Boundaries.** Start hits of one symbol lie on a line (the left edge), stop hits on another. A robust line fit (RANSAC) over hits of compatible module width and direction gives the left and right boundary segments; their extent gives top and bottom. Compact PDF417 has no stop pattern and no right row indicator: the right side ends at the single stop bar and is found while reading rows.
3. **Row sampling.** Lines parallel to the row direction, between the boundaries, spaced at most half a minimum row height (3 modules) apart. Each line is a gray profile; edges and runs as in `breader-linear`; codewords are read left to right after the start pattern: each is 4 bars and 4 spaces over 17 modules (widths 1–6), normalized and looked up in the cluster table. The cluster ((b1 − b2 + b3 − b4 + 9) mod 9 ∈ {0, 3, 6}) is the row number mod 3, which rejects most misreads for free.
4. **Grid assignment.** Row indicators (left and right columns) carry the row number, the row and column counts and the EC level. Lines get absolute row numbers from their indicators; lines without one are interpolated from neighbours (row numbers are monotonic across the symbol). Column positions come from the distance to the start pattern in 17-module units, re-anchored at each decoded codeword boundary. Every read votes into a rows × columns cell; the cell's value is the majority, and empty or tied cells are erasures.
5. **Metadata vote.** Rows, columns and EC level are taken by vote over all decoded row indicators; a symbol is accepted only when they agree with the grid extent and the symbol length descriptor (first data codeword).
6. **Error correction.** Reed-Solomon over the prime field GF(929) (generator 3), with erasures: Berlekamp–Massey with erasure initialization, Chien search and Forney, in `breader-ecc` next to GF(256). Misdecode guard (in `breader-pdf417`, not in the RS code): `2·errors + erasures ≤ ec − reserve`, with level 0 (2 check codewords) detection only and a reserve of 2 for up to 16 check codewords, 1 above. Cells above 928 count as erasures, and more erasures than the budget are rejected before decoding. When decoding fails, cells with a close second candidate are swapped in a bounded search.
7. **Decoding.** Decisions, with the sources behind them:
   - **Symbol length descriptor:** the first codeword must equal the number of codewords minus the check codewords (data, padding and the descriptor itself). Anything else is rejected.
   - **Text compaction:** four submodes with latches and shifts; latch 900 always restarts in Alpha. A shift left over at the end of a text run is the encoders' pad (odd sub-codeword count, 29) and is dropped; an invalid shifted value is rejected.
   - **Byte compaction:** five codewords make six bytes (a value of 2^48 or more is rejected). After 901 the byte count is not a multiple of 6, so the last one to five codewords of the run are single bytes (five codewords are five bytes, not a group); after 924 the run is whole groups only. Shift 913 is accepted in text mode only.
   - **Numeric compaction:** groups of up to 15 codewords; the base 900 value in decimal must be a 1 followed by at least one digit.
   - **ECI:** 927 (one codeword), 926 (two, 900 + 900a + b) and 925 (810900 + a) become `Charset::Eci(n)` segments, closed at the next ECI.
   - **Default character set:** ISO/IEC 15438:2006 sets the default interpretation to ISO/IEC 8859-1 (ECI 000003; the 1994 and 2001 texts used code page 437). Bytes outside an ECI are reported as one `Charset::Latin1` segment, the same declared default as Data Matrix, so `TextDecoder` needs no PDF417 rule.
   - **AIM identifier:** `]L2` for a symbol without ECI and `]L1` for a symbol that uses ECI (modifier 1 is the ECI-protocol form; this follows the repository's QR/Data Matrix convention of choosing the modifier from the symbol's content).
   - **Reader initialisation (921):** allowed as the first data codeword only; the decoder strips it and sets `reader_init`, and the reader will reject such symbols like Data Matrix reader programming.
   - **Macro PDF417:** 928, the segment index (two codewords, five digits with the numeric leading 1), the file ID (one or more codewords below 900, up to the next codeword of 900 or more), fields 923 + 0 to 6 (0, 3 and 4 text; 1, 2, 5 and 6 numeric; duplicates rejected) and the terminator 922. The control block is accepted anywhere but once; it is normally last, since the file ID takes every plain codeword that follows it. Reserved codewords (903–912, 914–920) and a 922 or 923 outside a block are rejected.
8. **Metadata.** `Pdf417Meta { rows, cols, ec_level, errors_corrected, erasures, compact, macro_pdf417 }`.

Fast effort uses fewer scanline directions. `PDF417` is not tried on frames where no start or stop pattern was seen, so its cost on other content is the run matching only.
