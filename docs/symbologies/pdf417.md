# PDF417 (`breader-pdf417`, milestone M9)

Design and implementation notes of the PDF417 and compact PDF417 reader (M9, implemented; the section [As built](#as-built) lists where the code departs from the design below). Part of the cross-cutting [architecture](../ARCHITECTURE.md) (pipeline, traits, validation policy); status, spec references and read rates are in the [symbology index](README.md).

Scope: PDF417 and compact (truncated) PDF417, all error-correction levels, Macro PDF417 control blocks (parsed into metadata), ECI. MicroPDF417 and GS1 composite components are deferred to the "micro" group. The normative source is ISO/IEC 15438.

**Tests:** rxing's encoder (Apache-2.0) is a dev-dependency, to encode test symbols only; the `pdf417` crate (MIT) does not build on stable, so it is not a dependency: its pattern tables are transcribed into `spec/clusters.rs` with attribution and checked exhaustively in tests (4 bars and 4 spaces of width 1 to 6 over 17 modules, the cluster formula, all 2787 patterns distinct), and its published check codewords are test vectors for `Gf929::encode`. Clean-room: no decoder sources are read.

PDF417 is a stacked linear symbology, so the reader works on gray profiles like `breader-linear` (`uses_binary() == false`), not on the binary plane. Edge detection and run extraction are reused from `breader-linear` through a small `#[doc(hidden)]` API rather than duplicated. Modules: `spec` (cluster tables, row-indicator formulas, EC sizes), `decode` (codeword matrix to payload), `scan` (a gray profile along any line to runs and pattern marks), `detect` (seed ranking, boundary growth and line fit), `row` (element widths to codewords, the walk along one line), `grid` (row numbers, layout vote, cell votes, retries around Reed-Solomon), `reader` (orchestration, quad, metadata), `geom` (vectors and the line fit).

1. **Start/stop search.** Scanlines from the linear scan plan (directions by effort). On the runs, match the start pattern (8 elements, 8-1-1-1-1-1-1-3 modules) and the stop pattern (9 elements, 7-1-1-3-1-1-1-2-1) with a quiet zone on the outer side, either reading direction. Each hit records position, module width and direction.
2. **Boundaries.** Start hits of one symbol lie on a line (the left edge), stop hits on another. A robust line fit (RANSAC) over hits of compatible module width and direction gives the left and right boundary segments; their extent gives top and bottom. Compact PDF417 has no stop pattern and no right row indicator: the right side ends at the single stop bar and is found while reading rows.
3. **Row sampling.** Lines parallel to the row direction, between the boundaries, spaced at most half a minimum row height (3 modules) apart. Each line is a gray profile; edges and runs as in `breader-linear`; codewords are read left to right after the start pattern: each is 4 bars and 4 spaces over 17 modules (widths 1–6), normalized and looked up in the cluster table. The cluster ((b1 − b2 + b3 − b4 + 9) mod 9 ∈ {0, 3, 6}) is the row number mod 3, which rejects most misreads for free.
4. **Grid assignment.** Row indicators (left and right columns) carry the row number, the row and column counts and the EC level. Lines get absolute row numbers from their indicators; lines without one are interpolated from neighbours (row numbers are monotonic across the symbol). Column positions come from the distance to the start pattern in 17-module units, re-anchored at each decoded codeword boundary. Every read votes into a rows × columns cell; the cell's value is the majority, and empty or tied cells are erasures.
5. **Metadata vote.** Rows, columns and EC level are taken by vote over all decoded row indicators; a symbol is accepted only when they agree with the grid extent and the symbol length descriptor (first data codeword).
6. **Error correction.** Reed-Solomon over the prime field GF(929) (generator 3), with erasures: Berlekamp–Massey with erasure initialization, Chien search and Forney, in `breader-ecc` next to GF(256). Misdecode guard (in `breader-pdf417`, not in the RS code): `2·errors + erasures ≤ ec − reserve`, with level 0 (2 check codewords) detection only and a reserve of 2 for up to 16 check codewords, 1 above. Cells above 928 count as erasures, and more erasures than the budget are rejected before decoding. When decoding fails, cells with a close second candidate are swapped in a bounded search.
7. **Decoding.** Decisions, with the sources behind them:
   - **Symbol length descriptor:** the first codeword must equal the number of codewords minus the check codewords (data, padding and the descriptor itself). Anything else is rejected.
   - **Text compaction:** four submodes with latches and shifts; latch 900 always restarts in Alpha. A shift left over at the end of a text run is the encoders' pad (odd sub-codeword count, 29) and is dropped; an invalid shifted value is rejected.
   - **Byte compaction:** five codewords make six bytes (a value of 2^48 or more is rejected). After 901 the byte count is not a multiple of 6, so the last one to five codewords of the run are single bytes (five codewords are five bytes, not a group); after 924 the run is whole groups only. Shift 913 is accepted in text mode only.
   - **Numeric compaction:** groups of up to 15 codewords; the base 900 value in decimal must be a 1 followed by at least one digit.
   - **ECI:** 927 (one codeword), 926 (two, 900 + 900a + b) and 925 (810900 + a) become `Charset::Eci(n)` segments, closed at the next ECI.
   - **Default character set:** ISO/IEC 15438:2006 sets the default interpretation to ISO/IEC 8859-1 (ECI 000003; the 1994 and 2001 texts used code page 437). Bytes outside an ECI are reported as one `Charset::Latin1` segment, the same declared default as Data Matrix, so `TextDecoder` needs no PDF417 rule.
   - **AIM identifier:** `]L2` for a symbol without ECI and `]L1` for a symbol that uses ECI (modifier 1 is the ECI-protocol form; this follows the repository's QR/Data Matrix convention of choosing the modifier from the symbol's content).
   - **Reader initialisation (921):** allowed as the first data codeword only; the decoder strips it and sets `reader_init`, and the reader returns the symbol with `Pdf417Meta::reader_init` set ([D-035](../decisions.md#d-035)), like Data Matrix and Aztec.
   - **Macro PDF417:** 928, the segment index (two codewords, five digits with the numeric leading 1), the file ID (one or more codewords below 900, up to the next codeword of 900 or more), fields 923 + 0 to 6 (0, 3 and 4 text; 1, 2, 5 and 6 numeric; duplicates rejected) and the terminator 922. The control block is accepted anywhere but once; it is normally last, since the file ID takes every plain codeword that follows it. Reserved codewords (903–912, 914–920) and a 922 or 923 outside a block are rejected.
8. **Metadata.** `Pdf417Meta { rows, cols, ec_level, errors_corrected, erasures, compact, macro_pdf417 }`.

Fast effort uses fewer scanline directions. `PDF417` is not tried on frames where no start or stop pattern was seen, so its cost on other content is the run matching only.

## As built

Everything in the list above is implemented. The differences and additions:

- **Where the start/stop search runs.** The pattern matcher lives in `breader-linear` (`marks.rs`) and is called from the linear reader's scan loop on every plan line, in both reading directions and both polarities, at the cost of one pass over the runs. The hits go into a `MarkSet` that the PDF417 reader finds in the frame context (`FrameContext::shared`, a small typed per-frame cache added to `breader-core`). There is no second scan: on `challenging-images` Balanced the median latency went from 16.75 to 17.0 ms (+0.25 ms; Fast +0.12, Exhaustive +0.7). When the linear reader did not run (only PDF417 enabled, or no `linear` feature) the PDF417 reader calls `breader_linear::stacked::scan_marks`, which scans the plan itself. A pattern that touches the profile border uses the margin as its first or last element, so tightly cropped symbols match. The matcher is only recorded when `ScanOptions::symbologies` contains PDF417.
- **Boundaries without RANSAC.** A seed (best-supported mark first) is grown by walking scan lines parallel to its direction on both sides; the expected position of the pattern on the next line comes from a least squares line over the last hits, and the walk ends after 10 misses. A robust fit (drop the worst residual until all are within 0.4 module + 0.5 px) gives the boundary, and the growth runs a second time over lines along the rows found, because a scan line crossing the pattern at a slant only sees the middle of the boundary. Stop patterns seed the right boundary the same way, so a symbol is found from either end.
- **Row lines.** Lines go from the boundary perpendicular to it, at 1.25 modules spacing (every pixel line when the rows lie on the pixel grid and the module is under 2.5 px, which is the only way to read rows a pixel high; lines along the grid are sampled on whole pixels, not interpolated). When the first pass fails, in order: lines between the start and the stop boundary through the perspective of their four ends (`Perspective::square_to_quad`); a pairing with a boundary grown from a pattern on the far side; rows turned by 2 to 16 degrees (constant turn, or a fan that turns opposite ways at the two ends), picked by the number of clean codewords on nine probe lines. A compact symbol has no stop boundary, so it relies on the turned and fanned hypotheses.
- **Codeword reading.** Boundaries are rounded cumulatively (no width is rounded on its own), up to three candidates per position are kept with their distance cost, and the candidate whose cluster agrees with the line's majority cluster wins. Clean boundaries then define a module grid (least squares over codeword starts) on which the codewords are read once more; this is more exact for pixels of a module or two. The cluster check is a vote, not a per-line gate: a line is dropped only when its best cluster has fewer than two codewords or less than twice the runner-up.
- **Grid.** Row numbers come from the left indicator, the right indicator (when the stop pattern was seen, which also gives the column count) or interpolation along the boundary by a median-slope fit; indicator reads that disagree with the fit by more than 1.5 rows are dropped. The layout is the vote of the three indicator fields (up to six combinations tried). Cells hold up to four candidate values with weights (clean 4, doubtful 3, second candidate 1); ties and empty cells are erasures. Retries inside the guard: erase the least certain cells in growing numbers, then put the runner-up value into the least certain cells. Lines cut short by the image border still fill the columns they have.
- **Decode fix found on the way.** An ECI designator inside a byte compaction run does not restart the groups of five codewords (the zxing-cpp sample `12-mixed-ecis`); a designator inside a group is still rejected.
- **Not done:** mirrored symbols (a vertical flip reads, a horizontal mirror does not), MicroPDF417, symbols below one pixel per module, 1 px modules (the shared edge detector merges them), compact symbols under strong perspective, the Macro PDF417 segments of `pdf417-4` (one file spread over several images; the labels are per file, so the set is not scored).
- **Reader initialisation (921)** symbols are returned with `reader_init` set ([D-035](../decisions.md#d-035)); `13-readerinit.png` reads from Balanced.
- **Budget.** Seeds tried per frame: 6 / 12 / 32 (Fast / Balanced / Exhaustive); tilt hypotheses: none / 3 / 5 angles; a smoothed-edge retry from Balanced. Seeds inside an already decoded quad, or on an already explored boundary, are skipped.
